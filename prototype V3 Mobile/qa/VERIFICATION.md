## 시뮬레이터에서 확인한 흐름

- Storyge 진입 → 나의 피드, 원형 사진 9개와 4개 탭 표시
- 피드 항목 선택 → 상세 → 이전 화면 복귀
- 추가 시트 표시, 빈 URL 오류 안내
- 테스트 링크·제목 저장, 앱 재진입 후 저장 항목 유지
- 검색어 입력 → 저장한 항목 1개 반환
- 즐겨찾기 변경 → 상세 화면 상태 반영
- 편집 시트에서 키워드·폴더 변경 → 저장 결과 반영
- 테스트 항목 삭제 → 검색 결과 0개, 삭제 실행 취소 버튼 표시
- 보관함 최신순 → 오래된순 변경: 항목 순서 변경
- 스크린샷 필터 → 4개 항목
- 폴더 → 공간·인테리어 하위 폴더 3개 → 전체 폴더 복귀
- 최종 피드는 기본 샘플 9개. 테스트용으로 추가한 링크는 삭제함

네이티브 이미지에 명시적 폭·높이를 적용해 원형 썸네일이 원본 크기로 잘리던 문제를 수정하고 화면에서 재확인했다.

## 미검증 및 한계

- Android 기기/에뮬레이터 실행, 실제 iPhone 실행, 햅틱 감각
- 피드 드래그·관성 및 iOS 가장자리 스와이프의 실기기 감각과 프레임률: 자동화의 좌표 드래그가 실패해 끝까지 검증하지 못함. 접근성 활성화로 상세 진입은 확인함
- 사진 선택 후 저장, 메모 저장/이탈 확인창, 새 폴더 생성, 외부 링크 앱 전환, 내보내기 공유 완료
- 삭제 실행 취소는 버튼 노출만 확인. 클릭 시점에 제한 시간이 지나 복원 완료 여부를 확인하지 못함
- VoiceOver/TalkBack·대형 글꼴·동작 줄이기 실제 설정별 사용성
- 저장소 오류/동시 쓰기 네이티브 통합 테스트. URL/입력/총 용량 검증은 모델 테스트로 확인
- 개발 중 파일 일괄 포맷과 Metro reload를 함께 수행한 직후 Expo Go 홈으로 돌아간 적이 있음. 최근 프로젝트에서 재진입한 후 정상 동작 및 데이터 유지 확인. 원인은 확정하지 않음

## 실행 환경

Node 26의 localhost가 IPv6에만 바인딩되어 최초 연결이 실패했다. 실행 스크립트에 `--dns-result-order=ipv4first`를 추가해 `127.0.0.1:8083` 연결을 확인했다. 개발 서버는 localhost에서만 열린다.

`ios-feed.jpg`는 실제 Simulator 화면이다. 우측 상단 파란 톱니는 Expo Go 개발 도구이며 Storyge UI 구성 요소가 아니다.
