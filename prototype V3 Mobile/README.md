# Storyge V3 Mobile

iOS·Android용 **React Native / Expo 네이티브 앱 시안**입니다. 웹 화면을 WebView로 감싼 프로젝트가 아닙니다. 기존 `prototype V3` 웹 버전과 V1·V2는 그대로 보관하며, 이 폴더는 소스·실행 환경·저장 데이터를 별도로 사용합니다.

현재 결과물은 **Expo Go에서 실행하는 개발용 시안**입니다. 서명된 독립 실행 IPA/APK, TestFlight 빌드, 스토어 출시본을 생성한 상태는 아닙니다.

## 실행

이 폴더에서 실행합니다. 처음 설치하거나 의존성을 다시 설치할 때는 `npm ci`를 사용하세요.

```sh
npm ci
npm run ios
```

| 명령 | 용도 |
| --- | --- |
| `npm start` | localhost:8083 개발 서버 시작 |
| `npm run ios` | 개발 서버와 iOS 시뮬레이터 실행 |
| `npm run android` | 개발 서버와 Android 에뮬레이터 실행 |
| `npm run typecheck` | TypeScript 검사 |
| `npm test` | 모델 테스트 12개 |
| `npm run export:check` | iOS·Android JS/Hermes 번들 내보내기 검사 |

실행 스크립트는 IPv4 우선 DNS 설정과 **localhost / 포트 8083**을 사용합니다. 이미 실행 중인 Metro 터미널이 있다면 새 서버를 중복 실행하지 말고 해당 터미널에서 `i` 또는 `a`를 누르세요. iOS에는 Xcode·시뮬레이터가, Android에는 Android SDK·실행 가능한 에뮬레이터가 필요합니다.

실물 기기 연결은 아직 설정·검증하지 않았습니다. 필요할 때 동일 Wi-Fi의 Expo Go 연결을 위해 개발자가 명시적으로 LAN 모드를 선택할 수 있습니다. LAN은 같은 네트워크에 개발 서버를 노출하므로 신뢰하는 네트워크에서만 사용하세요. 기본 스크립트는 LAN·터널을 열지 않습니다.

Expo Go에서 보이는 개발 메뉴·톱니바퀴는 개발 실행 환경의 UI이며 Storyge 출시 화면에 포함되는 앱 UI가 아닙니다.

## 실제 동작하는 범위

- 나의 피드·보관함·폴더·검색의 네 개 탭
- 원형 썸네일 피드의 터치·드래그, 네이티브 상세 화면 전환, 바텀시트
- 링크 저장, 사진 선택을 통한 이미지 저장, URL 형식·중복 검사
- 플랫폼·시간순·즐겨찾기 필터 및 제목·키워드·메모의 일반 텍스트 검색
- 폴더 생성, 항목의 폴더 이동, 제목·키워드 편집, 즐겨찾기, 메모
- 삭제와 실행 취소, 기기 로컬 영구 저장, 저장 오류 표시·재시도
- 저장된 원본 URL 열기·복사, JSON 텍스트 공유

초기 항목 9개는 **샘플**입니다. 샘플의 링크는 Unsplash 사진 출처이며, 실제 Instagram·YouTube 원본을 찾아낸 결과가 아닙니다. 새 링크의 플랫폼 판별은 URL 호스트 기반 규칙이며 AI 자동 분류가 아닙니다.

## 연결되지 않은 기능

AI 자동 분류, 스크린샷 원본 찾기, RAG·의미 검색, 다른 앱의 공유 메뉴에서 Storyge로 받는 **OS 공유 확장**, 계정·서버·기기 간 동기화는 구현 전입니다. 사진 선택기와 앱 내부의 공유 기능은 OS 공유 확장과 별개입니다.

백엔드·인증·운영 정책 및 실기기 검증을 포함한 출시 준비가 추가로 필요합니다. 검색·원본 탐색·공유 수신을 실제 서비스 수준으로 연결했다고 간주하면 안 됩니다.

## 저장·개인정보 제한

- AsyncStorage의 독립 키 `@storyge/mobile-v3/library-v1`을 사용합니다. 웹 V3 데이터와 연동하지 않습니다.
- Android 단일 저장값 읽기 제한을 피하기 위해 **전체 직렬화 데이터의 UTF-8 크기를 1.5MiB 이하**로 제한합니다. 한글·이미지 base64·메타데이터를 모두 합산합니다.
- 사진 선택 UI는 **약 800KB 이하 이미지**를 안내합니다. 선택 결과의 base64 문자열은 1,200,000자, 모델의 개별 이미지 데이터 URI는 1.2MiB 이하로 제한합니다. 원본 파일 크기와 재인코딩된 이미지 크기는 다를 수 있습니다.
- 모든 변경은 크기 검사와 실제 저장 성공 후 화면에 반영됩니다. 실패하면 메모리의 변경 전 상태를 유지하고 오류를 표시합니다. 손상된 저장 데이터는 자동 삭제·덮어쓰지 않습니다.
- 이 방식은 시안용입니다. 출시 버전은 이미지 파일 저장소와 메타데이터 DB를 분리해야 합니다.
- 저장 데이터는 **암호화되지 않습니다**. 민감한 정보는 넣지 마세요. 앱 삭제, Expo Go 데이터 삭제 또는 기기 변경으로 데이터가 사라질 수 있습니다.
- 안내 화면의 내보내기는 **JSON 텍스트를 공유**합니다. URL·메모·이미지 데이터도 포함되므로 공유 대상을 확인하세요. 현재 가져오기·복원 UI가 없으므로 내보내기를 검증된 백업/복구 기능으로 간주하지 마세요.

## 의존성 보안: 출시 전 해결 필요

`npm audit --omit=dev` 결과는 **26개 경고(High 19, Moderate 7, Critical 0)**입니다. 대부분 아래 세 advisory가 Expo·Metro·React Native 의존성 경로에 전파된 결과이며, 26개의 서로 다른 앱 런타임 취약점이 확인되었다는 의미는 아닙니다.

- [braces ≤3.0.3 — 깊게 중첩된 패턴의 DoS](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm): 현재 설치 3.0.3, 확인 시점에 패치 버전 없음.
- [node-forge ≤1.4.0 — RSA 서명 검증](https://github.com/advisories/GHSA-86w9-cpqp-85rv): 현재 설치 1.4.0, 확인 시점에 패치 버전 없음.
- [uuid <11.1.1 — 일부 buffer 인자의 경계 검사](https://github.com/advisories/GHSA-w5hq-g745-h8pq): 현재 xcode 경유 7.0.3. 확인한 xcode 호출은 `v4()`이며 advisory의 v3/v5/v6+buffer 경로는 확인되지 않았습니다.

이는 개발·빌드 도구 경로를 포함한 경고입니다. **upstream 패치와 영향 평가가 완료되기 전 출시 보안 검증은 통과 처리하지 않습니다.** 개발 서버를 localhost로 유지하고 비신뢰 패턴·인증서 입력을 피하세요. `npm audit fix --force`가 제안하는 Expo 44 / React Native 0.72 다운그레이드는 현재 프로젝트와 호환되지 않으므로 적용하지 않습니다. 호환되는 upstream 수정 후 재감사·빌드·실기기 회귀 테스트가 필요합니다.
