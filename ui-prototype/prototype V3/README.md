# Storyge · Prototype V3

Storyge의 세 번째 프론트엔드 시안입니다. `prototype V1`과 `prototype V2`는 수정하지 않고 보존했습니다. V3는 별도 폴더와 별도 브라우저 저장소를 사용합니다.

현재 버전은 실제 로컬 저장 기능이 있는 프론트엔드 프로토타입입니다. 계정·서버·AI 기능이 연결된 출시 서비스는 아닙니다.

## 실행

저장소 루트에서 `ui-prototype` 폴더로 이동한 뒤 실행합니다.

```sh
cd ui-prototype
python3 -m http.server 4173 --bind 127.0.0.1
```

[Storyge V3 열기](http://127.0.0.1:4173/prototype%20V3/index.html)

이미 4173 포트에서 같은 프로젝트 루트를 제공하는 서버가 실행 중이라면 새 서버를 시작할 필요가 없습니다. 서버를 실행한 터미널을 유지하세요. 종료하려면 해당 터미널에서 `Ctrl+C`를 누릅니다. `127.0.0.1` 바인딩은 현재 컴퓨터에서만 접근할 수 있으며 외부에 공개하지 않습니다.

`index.html`을 `file://`로 직접 여는 대신 위의 HTTP 주소를 사용하세요. 브라우저 저장소와 클립보드 등 웹 기능을 일관된 환경에서 확인할 수 있습니다.

## 현재 실제로 동작하는 기능

- 나의 피드·보관함·폴더·검색의 네 가지 메뉴, 데스크톱·모바일 화면 크기 대응
- 원형 썸네일 피드, 드래그 탐색 및 항목 상세 보기
- URL 또는 이미지 추가, 항목 조회·편집·삭제·삭제 직후 복원
- 제목·메모·키워드·폴더 편집, 새 폴더 생성, 즐겨찾기
- 플랫폼 필터, 저장 시점·제목 정렬, 격자·목록 보기
- 제목·키워드·메모·폴더·URL의 텍스트 일치 검색
- 사용자 입력 URL 보존·열기, 링크 복사
- IndexedDB 로컬 저장 및 JSON 내보내기
- URL 형식·중복 검사, 입력 길이 제한, 저장소 실패 안내

신규 항목에는 자동 분류 결과를 만들어 붙이지 않습니다. 사용자가 선택한 폴더에 저장하며, 기본 폴더는 `미분류`입니다. 새 이미지에 원본 URL이 없으면 없다고 표시합니다.

## 아직 연결되지 않은 기능

- AI 자동 분류·요약·키워드 추출
- 스크린샷에서 상품·게시물 원본 URL 검색
- 임베딩·벡터 데이터베이스·RAG 의미 검색
- iOS/Android 공유 확장 및 실제 웹 클리퍼 확장 프로그램
- 계정·로그인·기기 간 동기화·클라우드 백업
- 링크의 실제 제목·썸네일·본문 메타데이터 수집
- JSON 백업 가져오기 및 복원 UI

브라우저의 URL·이미지 추가 화면은 OS 공유 기능을 대신 구현한 것이 아닙니다. 플랫폼 이름이 YouTube·Instagram이라고 해서 해당 플랫폼 API에서 콘텐츠를 조회한 것은 아닙니다.

## 데이터 저장과 백업

- 저장 위치는 현재 브라우저의 IndexedDB입니다. 데이터베이스 이름은 `storyge-prototype-v3`입니다.
- 첫 실행 시에만 샘플 9개를 생성합니다. 새로고침해도 사용자 변경을 보존하며, 모든 항목을 삭제해도 샘플을 다시 생성하지 않습니다.
- 저장소 접근 또는 용량 문제 발생 시 임시 메모리 모드로 전환하고 경고합니다. 이 상태의 변경은 새로고침하면 사라질 수 있습니다.
- 브라우저 사이트 데이터 삭제, 브라우저 프로필 변경, 시크릿 모드 종료 또는 브라우저의 저장소 정리로 데이터가 사라질 수 있습니다. 서버 백업은 없습니다.
- `http://127.0.0.1:4173`과 `http://localhost:4173`은 서로 다른 출처(origin)입니다. 같은 파일을 열어도 보관함 데이터가 분리됩니다. 포트나 프로토콜을 바꿔도 마찬가지입니다. 테스트 내내 같은 주소를 사용하세요.
- 도움말 화면의 **저장 데이터 내보내기**로 `storyge-backup.json`을 다운로드할 수 있습니다. 파일에는 이미지 데이터·메모·URL이 포함되므로 공유 전 개인 정보를 확인하세요.
- JSON은 현재 수동 보관용 데이터 사본입니다. 앱으로 다시 가져오는 기능은 아직 없습니다. 이를 검증된 자동 복구 수단으로 간주하면 안 됩니다.

## 샘플 이미지와 출처

V2에서 사용하던 9개의 Unsplash 샘플 사진을 `assets/`에 재사용했습니다. 각 샘플의 `url`에는 기존 Unsplash 이미지 출처 주소를 보존했습니다. 상세 화면에서도 샘플임을 표시하며, 사진 링크가 실제 영상·상품 원본 링크인 것처럼 표시하지 않습니다. 샘플 플랫폼과 저장 날짜는 시각적 시연을 위한 예시입니다.

`assets/books.jpg`는 기존 파일명을 유지하지만 사진 내용에 맞춰 신규 샘플 제목을 **데스크 조명**으로 설정했습니다. 이 변경은 이미 저장된 사용자 항목이나 기존 샘플의 제목을 덮어쓰지 않습니다.

## 기술 구성

- Vanilla HTML·CSS·JavaScript, 빌드 단계나 UI 프레임워크 없음
- CSS 전환·Web Animations API 및 직접 구현한 피드 상호작용
- `prefers-reduced-motion` 대응
- IndexedDB 로컬 저장
- 로컬 번들 [Lucide](https://lucide.dev/) **1.51.0** 아이콘

Lucide의 ISC 및 일부 Feather 유래 아이콘의 MIT 고지는 `vendor/LUCIDE-LICENSE`에 포함되어 있습니다. 해당 파일을 배포물에도 유지하세요. Motion·Sonner·Vaul 패키지를 설치하거나 실행하지는 않았습니다. 관련 디자인·동작 원칙을 참고해 현재 코드 구조에 맞게 구현했습니다.

주요 파일:

| 파일 | 역할 |
| --- | --- |
| `index.html` | 진입 페이지와 앱 구조 |
| `styles.css` | 반응형 레이아웃·컴포넌트·전환 스타일 |
| `app.js` | 화면 전환·폼·상세·검색·편집·내보내기 |
| `orbit.js`, `orbit.css` | 원형 썸네일 피드 상호작용 |
| `store.js` | 데이터 검증·CRUD·IndexedDB 영속 저장 |
| `store.test.cjs` | 저장 계층 자동 테스트 |
| `vendor/` | 아이콘 번들과 라이선스 |
| `assets/` | V2에서 가져온 샘플 이미지 |

## 검증

[브라우저 검증 기록과 화면 캡처](qa/QA.md)를 함께 보관했습니다. 메모는 상세 화면을 닫을 때도 자동 저장하며, 실패하면 화면을 유지하고 원인을 표시합니다.

V3 폴더에서 다음 명령으로 저장 계층 테스트를 실행합니다. Node.js 외 추가 패키지는 필요하지 않습니다.

```sh
node --test store.test.cjs
```

자동 테스트 6개가 다루는 범위:

1. 명시적인 메모리 폴백, 샘플 표기, 반환 값의 방어적 복사
2. 안전한 URL·플랫폼 호스트 판별, 중복 URL 및 동시 저장 방지
3. 이미지 데이터 유지, 식별자 보호 및 위험한 객체 속성 무시
4. 필드 제한, 폴더 생성, 편집·삭제·복원·내보내기
5. 재초기화 후 저장 데이터 복원, 빈 보관함에서 샘플 재생성 방지
6. 저장 공간 부족 시 세션 데이터 보존 및 비영속 상태 안내

영속 저장 테스트는 비동기 IndexedDB 경계 테스트 더블을 사용합니다. 이 결과는 실기기 Safari·Chrome의 저장소 동작, 터치 제스처, VoiceOver 또는 하드웨어 E2E 검증을 대신하지 않습니다.

## 실제 출시 전 체크리스트

- 인증·권한·API 계약·동기화 충돌 처리·서버 데이터베이스·백업/복구 구현
- AI 분류·원본 검색·의미 검색 연결, 불확실한 결과와 재시도 상태 설계
- OS 공유 확장/웹 클리퍼, 플랫폼별 URL 처리·썸네일 권한·딥링크 검증
- 사용자 파일 업로드 보안, 서버 URL 조회의 SSRF 방지, 요청·용량 제한
- 데이터 삭제·내보내기/가져오기, 개인정보 처리방침·보존 기간·이미지 권리 확인
- iOS Safari·Android Chrome 실기기에서 제스처·키보드·화면 읽기·모션 축소·성능 검증
- 오류 추적·접속 장애·저장 실패·동시 탭/다중 기기 충돌 및 복구 테스트
- HTTPS 배포·캐시 업데이트·운영 모니터링·지원 경로 준비

V3는 이러한 서버·운영 작업의 기반이 되는 프론트엔드이며, 체크리스트 완료 전 실제 서비스 출시가 검증되었다고 보지 않습니다.
